UI Redesign v2 · 全横屏 · 待评审

车机投屏 · 界面改版设计稿 v2

启动只给两个入口，演示模式负责无人值守地自动投屏，设置负责设备和参数管理；全部页面按横屏排版，投屏页铺满且不叠加任何控件。

目标设备 TB522FU 物理尺寸 3840 × 2560 px 逻辑尺寸 1536 × 1024 dp 密度 400 dpi @2.5× 方向 全横屏锁定 主题 Material 3 深色

开发门禁：本文件只到设计稿。下面每块画板都是 3840 × 2560 px 的等比稿（内容按 dp 编排后整体 ×2.5），你确认版式、文案和交互规则之后我再动代码。

01设计依据

版式取自 Google 官方的大屏规范，交互模型取自几个成熟 scrcpy 图形客户端，再按这台平板「横屏手持、站在车边操作」的实际用法收敛成两层结构。

从大屏规范里取的

  • Window size class = expanded：1536 × 1024 dp 属于 expanded，横向空间充足，用「并排卡片 + 双栏」而不是单列长页。
  • List-Detail 规范布局：设备管理、设置概览都用左右分栏，避免「点进去、返回、再点进去」。
  • 可点区域 ≥ 48 dp：本稿主按钮 68 dp、列表行 100 dp 以上，单手拿着平板也点得中。
  • 正文行宽 ≤ 60 字符：说明文字限制在 640–700 dp，避免横屏一行太长。

从 scrcpy 客户端里取的

  • 设备列表常驻 + 状态内联（Escrcpy、go-scrcpy-client）：设备行直接显示「USB / 无线 · 已连接 / 待授权」，不需要额外状态页。
  • 参数按组折叠（Scrcpy GUI Flutter 版的分组面板）：本稿收敛成「区域 / 画质 / 高级」，并加实时裁切预览。
  • 一键无线连接：保留「地址 + 端口 + 记住此设备」，连上后自动成为演示模式首选。
  • 刻意不做：多设备并行投屏、命令预览、键盘映射——这台平板只服务一台车机。

这一版的最大变化：v1 是竖屏稿（1024 × 1536 dp）。你现在用横屏平板，投屏页本来就锁横屏，所以 v2 把所有页面统一到 1536 × 1024 dp 横屏。版式随之重排：首页两张卡并排、演示模式改成「左图右文」、设置与投屏设置改成双栏、设备管理加宽列表。

05投屏页的三条硬要求

这一版按你的要求重做，和原版的行为差异都写在下面，避免开发时又回到旧逻辑。

1. 去掉 3 秒退出按钮

  • 不再有 × 浮窗，也不再有「按住 3 秒退出」气泡；投屏页上不叠加任何常驻 UI。
  • 退出改用系统返回手势：从屏幕左/右边缘向内滑。左右各留 40 dp 给系统手势区，这 40 dp 不再转发给车机（实际影响：车机画面最外侧约 2.6% 宽度的点击落不到）。
  • 可发现性靠一次性提示：新装或改过投屏区域后的第一次进入，顶部显示「从屏幕边缘内滑可退出投屏」，3 秒后自动消失，之后不再出现。
  • 如果现场担心误触退出，可选加「退出前需在 2 秒内连续两次边缘内滑」；默认不加。

2. 铺满整个屏幕，不留白

  • 缩放策略从「fit-center（等比缩小 + 居中留边）」改成 cover（等比放大 + 居中裁切），四边贴边，没有任何黑边或白边。
  • 实测现状：原版 3840 × 2560 的投屏截图里，顶部约 110 px、底部约 48 px 是纯白（RGB 250,250,250）——这就是你说的上下两个白框。原因是 VideoGeometry 用 fit-center 算内容区，未覆盖的部分露出了窗口背景色。
  • 代价是裁切，且比例差越大裁得越多：仅主屏（2560 × 1600 = 1.6:1）对 1.5:1 的横屏只裁约 6% 宽度；全屏（5120 × 1600 = 3.2:1）要裁掉约 53% 宽度。所以建议演示默认用「仅主屏（左）」，并在投屏设置里对比例差过大的选择给出提示。

3. 单屏车机不能被切半

  • 投屏设置新增屏幕类型：单屏（整屏投放）或双联屏（左右各半）。默认单屏，整幅画面直接投放，不裁不放大。
  • 只有选了双联屏，区域里才出现「仅主屏（左）／仅副屏（右）」；单屏设备即使之前存过主/副屏，读取时也会纠正为全屏。
  • 原因：旧逻辑对所有设备都按宽度对半切，单屏车机（如 1920 × 1080）会被裁掉一半再铺满，画面被放大到失真。
  • 判断依据可参考 DisplayLayout.looksDual：宽高比 ≥ 2.8（T26FL 为 5120 × 1600 = 3.2）才像双联屏；仅作默认建议，最终以用户选择为准。

4. 分辨率跟随车机

  • 连上设备后自动读取 wm size，默认按车机实际分辨率编码（跟随车机分辨率），不再固定 2560。
  • 实现上把 max_size 设为「最长边向上取 16 的倍数」，scrcpy 只在超过该值时才缩放，因此单屏车机输出就是原分辨率，没有二次缩放。
  • 需要压带宽时切到「自定义最长边」手动限制；单屏默认整屏投放，不裁不放大。

5. 全应用横屏

  • 不只是投屏页：首页、演示模式、设置、设备管理、无线连接、投屏设置全部按 1536 × 1024 dp 横屏排版，Manifest 里统一锁 SCREEN_ORIENTATION_LANDSCAPE。
  • 投屏页旋转过程中不重启会话（沿用现有 configChanges 处理）。
  • 触控映射要按裁切后的可视区重算：内容区以屏幕中心对齐，坐标先减裁切偏移再按 cover 比例换算，不能沿用 fit-center 的换算。

对实现的连带影响（确认后再动代码）：①VideoGeometry 增加 cover 模式与裁切偏移；②MirrorActivity 去掉 ExitHandle、增加一次性提示；③ 返回手势用 OnBackPressedDispatcher 直接结束投屏；④ 触控换算改用裁切偏移；⑤ 首页重做成两张入口卡，设置与投屏设置改为双栏；⑥ Manifest 全局锁横屏；⑦ 投屏设置里对比例差 > 15% 的区域显示裁切比例提示。

06交互与状态规则

演示模式的目标选择

  1. 进页面先看「设置里选中的 ADB 设备」：有就直接连它，不等 USB。
  2. 没有选中设备（或连续两次连接失败）再监听 USB 插入；插上就自动走 USB，并在状态行写「无线不可达，已切换到 USB」。
  3. 两者都不可用时停在「等待 USB 设备接入」，每 3 秒重试一次首选无线目标；失败不弹窗，只在状态行显示原因。
  4. 连上后直接进投屏页，参数取该设备已保存的设置；没有记录时用默认值：仅主屏 / 2560 边 / 8 Mbps / 30 fps。
  5. 仅在应用前台监听；切后台停止，回前台重新检查（与现有实现一致）。
  6. USB 首次接入需要系统授权：授权框由系统弹出，只在本应用窗口获得焦点时才可靠。等待页在需要授权时提供「允许 USB 访问」按钮，窗口重获焦点也会自动重试一次。

  • 错误只说「发生了什么 + 怎么修」，不出现异常类名和英文堆栈；原始异常写日志。
  • 参数摘要统一格式：区域 · 帧率 · 码率，例如「仅主屏 · 30 fps · 8 Mbps」。
  • 按钮动词化：连接 / 断开 / 重试 / 保存到这台设备；不用「确定」。
  • 需要用户去车机上操作时，明确写「在车机上…」，并说明只需一次。
