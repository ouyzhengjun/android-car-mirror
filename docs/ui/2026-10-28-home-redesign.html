车机投屏 · 界面改版设计稿 v1

把「一屏堆满所有控件」改成「先选模式，再进设置」：启动只给两个入口，演示模式负责无人值守自动投屏，设置负责设备和参数管理。

目标设备 TB522FU 物理分辨率 2560 × 3840 px 逻辑尺寸 1024 × 1536 dp 密度 400 dpi @2.5× 主题 Material 3 深色 投屏页 3840 × 2560 px 横屏

开发门禁：本文件只到设计稿。下面每块画板都是 2560 × 3840 px 的等比稿（内容按 dp 编排后整体 ×2.5），你确认版式、文案和交互规则之后我再动代码。

01设计依据

版式取自 Google 官方的大屏规范，交互模型取自几个成熟 scrcpy 图形客户端，再按这台平板的实际用法收敛成两层结构。

从大屏规范里取的

  • Window size class = expanded：1024 dp 宽属于 expanded，用「单栏 + 分区卡片」推进，不做手机式的层层套娃。
  • List-Detail 规范布局：设备管理用左列表 400 dp + 右详情双栏，避免「点进去、返回、再点进去」。
  • 可点区域 ≥ 48 dp：本稿按钮 70 dp、列表行 100 dp 以上，站在车边单手点得中。
  • 正文行宽 ≤ 60 字符：说明文字全部限制在这个范围内。

从 scrcpy 客户端里取的

  • 设备列表常驻 + 状态内联（Escrcpy、go-scrcpy-client）：设备行直接显示「USB / 无线 · 已连接 / 待授权」，不需要额外状态页。
  • 参数按组折叠（Scrcpy GUI Flutter 版的分组面板）：本稿收敛成「区域 / 画质 / 高级」三段，并加实时裁切预览。
  • 一键无线连接（多款客户端的 USB→TCP/IP 流程）：保留「地址 + 端口 + 记住此设备」，连上后自动成为演示模式首选。
  • 刻意不做：多设备并行投屏、命令预览、键盘映射——这台平板只服务一台车机，复杂度只会变成误操作。

与现状的差别：现在是一个可滚动长页面（设备、模式开关、投屏参数全挤在一屏，底部按钮要滚很久才出现）。改版后主页只有两个入口；演示模式独占一页且只有「等待 / 连接中 / 投屏中 / 失败」四态；设置拆成设备管理、无线连接、投屏设置三个页面。

03信息架构

只有两层，任何页面最多一次「返回」就回到首页。

页面职责能去哪
首页整屏只有两个入口：演示模式 / 设置，不放任何状态或快捷操作演示模式、设置

投屏设置区域（全屏/主屏/副屏/自定义）与画质，带裁切预览，按设备保存设备管理

05投屏页的三条硬要求

这一版按你的新要求重做，和原版的行为差异都写在下面，避免开发时又回到旧逻辑。

1. 去掉 3 秒退出按钮

  • 不再有 × 浮窗，也不再有「按住 3 秒退出」气泡；投屏页上不叠加任何常驻 UI。
  • 退出改用系统返回手势：从屏幕左/右边缘向内滑。左右各留 40 dp 给系统手势区，这 40 dp 不再转发给车机（实际影响：车机画面最外侧约 2.6% 宽度的点击落不到）。
  • 可发现性靠一次性提示：新装或改过投屏区域后的第一次进入，顶部显示「从屏幕边缘内滑可退出投屏」，3 秒后自动消失，之后不再出现。
  • 如果现场担心误触退出，可选加「退出前需在 2 秒内连续两次边缘内滑」；默认不加。

2. 铺满整个屏幕，不留白

  • 缩放策略从「fit-center（等比缩小 + 居中留边）」改成 cover（等比放大 + 居中裁切），四边贴边，没有任何黑边或白边。
  • 实测现状：原版 3840 × 2560 的投屏截图里，顶部约 110 px、底部约 48 px 是纯白（RGB 250,250,250）——这就是你说的上下两个白框。原因是 VideoGeometry 用 fit-center 算内容区，未覆盖的部分露出了窗口背景色。
  • 代价是裁切，且比例差越大裁得越多：仅主屏（2560 × 1600 = 1.6:1）对 1.5:1 的横屏只裁约 6% 宽度；全屏（5120 × 1600 = 3.2:1）要裁掉约 53% 宽度，等于只看得到中间一部分。所以建议演示默认用「仅主屏（左）」，并在投屏设置里对比例差过大的选择给出提示。

3. 只支持横屏

  • 投屏页锁定 SCREEN_ORIENTATION_LANDSCAPE，物理尺寸 3840 × 2560 px（1536 × 1024 dp）；其余页面锁定竖屏。
  • 进入投屏时旋转到横屏、退出时回竖屏；旋转过程中不重启会话（沿用现有 configChanges 处理）。
  • 触控映射要按裁切后的可视区重算：内容区以屏幕中心对齐，坐标先减裁切偏移再按 cover 比例换算，不能沿用 fit-center 的换算。

对实现的连带影响（确认后再动代码）：①VideoGeometry 增加 cover 模式与裁切偏移；②MirrorActivity 去掉 ExitHandle、增加横屏锁定与一次性提示；③ 返回手势用 OnBackPressedDispatcher 直接结束投屏；④ 触控换算改用裁切偏移；⑤ 投屏设置里对比例差 > 15% 的区域显示裁切比例提示。

06交互与状态规则

演示模式的目标选择（按你的第 2 条）

  1. 进页面先看「设置里选中的 ADB 设备」：有就直接连它，不等 USB。
  2. 没有选中设备（或连续两次连接失败）再监听 USB 插入；插上就自动走 USB，并在状态行写「无线不可达，已切换到 USB」。
  3. 两者都不可用时停在「等待 USB 设备接入」，每 3 秒重试一次首选无线目标；失败不弹窗，只在状态行显示原因。
  4. 连上后直接进投屏页，参数取该设备已保存的设置；没有记录时用默认值：全屏 / 2560 边 / 8 Mbps / 30 fps。
  5. 仅在应用前台监听；切后台停止，回前台重新检查（与现有实现一致）。

状态视觉可用动作

文案规则

  • 错误只说「发生了什么 + 怎么修」，不出现异常类名和英文堆栈；原始异常写日志。
  • 参数摘要统一格式：区域 · 帧率 · 码率，例如「全屏 · 30 fps · 8 Mbps」。
  • 按钮动词化：连接 / 断开 / 重试 / 保存到这台设备；不用「确定」。
  • 需要用户去车机上操作时，明确写「在车机上…」，并说明只需一次。
