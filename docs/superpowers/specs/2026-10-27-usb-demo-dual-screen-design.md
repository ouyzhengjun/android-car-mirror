# USB ADB、演示模式与双联屏投屏改造设计

日期：2026-10-27

## 目标与现场设备

在现有单 APK 车机投屏应用上增加平板 USB Host 直连车机 ADB、前台演示模式、三块式主页和可配置的投屏区域。无线 TCP ADB 与现有命令、scrcpy 投屏、触控和拖动长按 3 秒退出能力继续可用。

当前验收设备：联想 TB522FU 平板，Android 15 / API 36，声明 `android.hardware.usb.host`；T26FL 车机的无线 ADB 为 `192.168.43.160:5555`，Android 14 / API 34，display 0 为 `5120×1600`。用户确认主屏是左半 `2560×1600`，副屏是右半 `2560×1600`。车机还报告若干 HDMI/虚拟显示器；本次主副屏指 display 0 的左右两半，不把虚拟 `right_display` 当作副屏。

## 方案选择

1. **选用：纯 Java USB Host ADB 传输。** 用 Android `UsbManager` 枚举/授权 ADB 接口，以 bulk IN/OUT 实现 ADB 协议，接入现有 `AdbSession.Transport`。同一套上层 shell、sync、scrcpy、视频和触控逻辑可同时用于 USB 与 TCP；不加入原生 ABI 依赖。USB 读写、认证、取消、拔线与流控必须专门测试。
2. 改造 `libadb-android` 使其底层支持 USB 字节流：复用其协议实现，但该版本把连接绑定在 Socket 构造过程，维护 fork 的范围较大。
3. 原生 AOSP adb/libusb：需要多 ABI 打包及额外权限桥接，当前 Java 单 APK 无此必要。

现有 `libadb-android:3.1.1` 继续负责 TCP；USB 采用应用内独立纯 Java ADB 实现，不要求电脑中转、root 或车机端安装应用。用户已选择此路径。

## 主页和操作流程

主页改为三块纵向区域，平板横竖屏均可滚动：

```text
┌ ADB 设备 ───────────────────────────────┐
│ USB：已发现 / 等待授权 / 已连接 / 已拔出 │
│ 无线：已保存的 IP:端口、连接状态         │
│ 选择设备 · 添加/连接无线 · 断开 · 命令   │
├ 模式选择 ───────────────────────────────┤
│ 演示模式 [开/关] · 状态/等待提示          │
│ 后续模式的扩展入口                       │
├ 投屏设置 ───────────────────────────────┤
│ 区域：全屏 / 仅主屏 / 仅副屏 / 自定义     │
│ 显示器 ID、最长边、码率、帧率            │
│ 开始投屏                                │
└─────────────────────────────────────────┘
```

设备区展示当前可见的 USB ADB 设备及已保存的 TCP 地址。USB 设备用产品名、VID/PID 和可读取的序列号区分；同名设备仍显示不同的 USB 路径。设备列表可选择一个目标连接或操作，同一时间只有一个活动 ADB 会话。无线地址由用户添加或选择，不自动扫描局域网。

演示模式**只监听有线 USB ADB**，不扫描或自动连接无线地址；应用处于前台（主页或投屏页）时持续监听。已有 USB 设备会立即进入候选列表；后插入设备由 USB attach 事件触发，拔线由 detach 事件清理。如果只有一个可用 USB ADB 设备，应用请求系统 USB 授权、完成 ADB RSA 授权后自动投屏。如果同时有多个，停在设备选择状态，用户选定一个后自动投屏。权限拒绝、ADB 认证超时或 scrcpy 启动失败时显示原因并保持监听，允许再次选择/重试。演示模式关闭时不再自动启动；手动无线与 USB 连接仍可使用。

投屏页长按退出图标满 3 秒时关闭本次 scrcpy 会话，**同时关闭演示模式**并返回主页，避免仍插着 USB 时立刻再次自动投屏。意外拔线时投屏页退出并回到监听状态，若设备重新插入可再次自动启动。应用退到后台后停止演示监听；重新进入前台时按当前 USB 列表恢复等待，不从后台强行弹出页面。无需前台服务或开机自启。

## USB ADB 传输

仅识别 USB 接口类/子类/协议 `0xff/0x42/0x01`，找出 bulk IN 与 bulk OUT 端点。通过 `UsbManager.requestPermission` 请求每台设备的用户授权；未获授权前不访问端点。连接由后台线程执行，独立超时和取消；设备拔出时关闭 `UsbDeviceConnection`、所有 ADB 流及投屏会话。

USB 后端实现 ADB `CNXN/AUTH/OPEN/OKAY/WRTE/CLSE` 及同步读写：复用应用私有 RSA 身份文件；每个打开的服务向现有 `AdbChannel` 暴露输入/输出流，支持 shell、sync 和 `localabstract:scrcpy_...`。包头、长度、校验、最大包与流 ID 均验证；部分 bulk 读/写必须循环完成，写入等待远端 `OKAY` 并支持取消，不能把零字节读当作 EOF。一个 USB 连接有单独收包/分发线程，屏幕视频与控制流可并行。连接失败不影响已保存无线连接项。

USB 物理验收需要平板切换为 OTG Host，线缆接到**实际暴露 ADB device 功能**的车机 USB 调试口。平板当前用同一 USB 口连接开发电脑，不能同时以 Host 角色连车机；实现后需改用平板的无线调试观察日志，再换接 OTG 线进行端到端测试。若车机接口仅是 USB Host 或不暴露 ADB 接口，应用应明确显示“未发现 USB ADB 设备”，不能声称有线连接成功。

## 投屏设置与双屏裁切

设置按所选设备保存，并在启动投屏时形成不可变快照。区域预设：

| 选项 | T26FL display 0 上的 scrcpy v4 `crop` |
| --- | --- |
| 全屏 | 不传 `crop`，完整 `5120×1600` |
| 仅主屏 | `crop=2560:1600:0:0` |
| 仅副屏 | `crop=2560:1600:2560:0` |
| 自定义 | 用户输入 `宽×高+x+y`，须在目标显示器的原始尺寸内 |

默认 display ID 为 `0`；首次读取到 display 0 恰为 `5120×1600` 时默认区域为“仅主屏”，其他设备默认“全屏”，已有保存设置优先。设置区可调整 display ID（0–255）、最长边 `max_size`（默认 2560，允许 256–8192 的 16 倍数）、视频码率 `video_bit_rate`（默认 8 Mbps，允许 1–50 Mbps）和 `max_fps`（默认 30，允许 1–60）。裁切参数为正整数，宽高为偶数，且 `x+宽`、`y+高` 均不得超过目标显示器尺寸。无法读取显示尺寸时可用全屏，主/副/自定义提示先读取设备尺寸。全屏画面可按最长边缩放以降低负载；主/副屏在 server 端裁切后再编码，平板上的视频和触控坐标仍按返回的视频流尺寸计算。客户端**不再额外为副屏触控加 x 偏移**，由 scrcpy 服务端把裁切后触点映射回原始 display 0。

视频尺寸变化、旋转或重连时重新应用已选区域与参数；如果裁切区域已超出新的显示边界，停止投屏并显示可修改的设置错误，不能发送落到错误屏幕的触控。投屏会话仍保留原来的 3 秒退出浮窗和无音频策略。

## 验收与限制

- 单元测试覆盖 USB 枚举过滤、部分包/零读/拔线、RSA 授权、ADB 流并发与取消、候选设备数量、演示模式状态机、投屏设置边界、scrcpy 启动参数以及左右裁切的触控映射。
- 在当前 TB522FU 与 T26FL 上验证无线手动连接、三块主页、显示尺寸读取、全屏/主屏/副屏画面及左右触控落点、设置持久化、长按退出不自动重启。
- 在 OTG 直连后验证 USB 授权、车机 RSA 授权、命令、scrcpy 视频与触控、拔线恢复和多 USB 设备选择。此项取决于车机调试口实际 USB device 能力。
- 演示模式仅在应用前台工作；无线 ADB 只手动连接；无局域网扫描、后台服务或开机自启。最低 Android API 21 不变，当前平板 API 36 为优先实测设备，未实测版本在交付记录中标明。
