# 平板无线 ADB 车机投屏应用设计

日期：2026-10-20

## 目标与验收

制作可直接安装在 Android 平板上的单 APK。用户输入车机无线 ADB 的 IP 和端口，完成连接与首次 RSA 授权后，在平板内全屏查看车机画面，点击、拖动、滑动可控制车机。投屏上方有可拖动的小图标，原地按住满 3 秒退出并回到设备页。应用提供设备连接管理和简单 ADB 命令的输出。

首个真机验收环境：华为 DBY-W09 平板，Android 12 / API 31，1600×2560；预填车机地址 `192.168.42.147:5555`。平板已通过 USB 连接开发电脑，平板到车机地址的 ICMP 检查成功。车机 Android 版本和实际 ADB 授权状态尚待真机连接确认。

## 范围

- 平板 Android 5.0（API 21）及以上，优先验证现有 Android 12 平板；不同分辨率和方向自动适配。
- 车机 Android 5.0（API 21）及以上，启用经典 TCP 无线 ADB，可从平板网络到达，并允许车机端确认 RSA 授权。
- 单设备投屏会话；设备页可保存和切换多个 `IP:端口` 连接项，同一时间只控制一个车机。
- 视频 H.264、远程触控和基础系统按键。音频、文件传输 UI、无线调试配对码、USB ADB、录屏暂不属于本次验收。
- “内置 ADB”指 APK 内含 ADB 协议客户端能力，提供连接、断开、查看状态、执行 `shell` 命令及读取输出；不在 Android 上运行桌面版 `adb` 可执行文件。命令入口显示清楚的目标设备并保留最近输出。
- “内置 scrcpy”指 APK 内含固定版本 `scrcpy-server`，并实现与其版本匹配的 Android 客户端协议；不在 Android 上运行桌面 SDL/FFmpeg 客户端。

## 方案选择

选择原生 Android 客户端：ADB 协议连接车机，将 scrcpy server 推送至车机并以 `shell` 权限启动，通过 ADB 的 `localabstract` 服务读取视频和控制通道，使用平板 `MediaCodec` 解码。该方案无需电脑中转、root 或本机悬浮窗权限。

曾考虑移植桌面 scrcpy 客户端，其 SDL/FFmpeg 依赖需要多 ABI 构建与维护；也考虑电脑中转，但不满足平板独立工作。固定 scrcpy v4.0 的 server 与协议，升级时必须成对验证，不能单独替换 server。

## 模块与数据流

1. **设备页 / 命令页**：编辑和保存连接项，显示 `连接中 / 待车机授权 / 已连接 / 断开`，提供连接、断开、开始投屏。命令页支持少量设备管理命令和 `adb shell <命令>`，异步显示标准输出、错误及超时。IP 地址和端口分别校验；默认项为 `192.168.42.147:5555`。
2. **ADB 会话**：生成并在应用私有目录保存 RSA 密钥；与车机 adbd 完成认证，复用连接打开 shell、sync、`localabstract` 流。设备页显示可读错误（超时、端口拒绝、未授权、离线）。网络断开时关闭全部流并复位状态。
3. **scrcpy 会话**：从 APK 资源读取固定版本 server，以 ADB sync 推送至 `/data/local/tmp/`，在车机启动 `app_process`。使用独立随机 `scid` 和 `tunnel_forward=true`，关闭音频；按 v4.0 协议读取视频和控制流。启动失败时清理流与进程；退出时结束会话并返回设备页，ADB 设备连接可继续供命令页使用。
4. **画面**：解析 scrcpy 元数据、H.264 配置帧与媒体帧，送入 `MediaCodec` 输出到 `SurfaceView`。车机画面按比例完整显示；旋转或分辨率变化时重配解码器和坐标映射。解码滞后时优先保持低延迟，断流给出可恢复状态。
5. **交互**：把 `SurfaceView` 内的触摸位置换算到视频坐标，发送 scrcpy 触控控制消息；支持单点点击、按住、滑动、多指基础事件。提供返回、主页、最近任务按键。黑边不接收触控。按钮和退出图标的触摸不转发给车机。
6. **退出图标**：仅显示在投屏 Activity 内，可在安全显示区域拖动。原地持续按住 3 秒触发退出，并显示倒计时进度；手指提前抬起或移动超过拖动阈值则取消计时，拖动只改变位置。无系统级悬浮窗权限请求。

## 生命周期与兼容

- 网络与协议读写均在后台线程；UI 只接收状态。每个连接和投屏启动可取消，带明确超时。
- Activity 暂停或 Surface 丢失时暂停/重建解码；用户退出、系统销毁、车机断线时按同一清理路径关闭控制、视频、解码器和远端 server，避免残留控制会话。
- 使用 Android 公共 API 和 H.264 硬件/系统解码能力，不打包原生可执行文件，以减少 CPU ABI 差异。运行时检测可用解码器并报告不支持情形。
- ADB 私钥只在应用私有存储。仅连接用户输入的地址；不自动扫描局域网，不在日志记录私钥或完整敏感命令输出。经典 TCP ADB 的使用前提是车机在受信任网络中开放调试端口。

## 验证

1. 单元测试：地址与端口校验、ADB/scrcpy 帧解析、视频坐标映射、退出图标的 3 秒状态机。
2. 构建 debug APK，在已连接 DBY-W09 平板上安装。
3. 真机端到端：连接 `192.168.42.147:5555`；在车机确认 RSA 授权；读取设备信息与命令输出；启动投屏；验证点击、长按、滑动、返回/主页、画面旋转；拖动图标并按住 3 秒退出；断网后重连。
4. 在可用的其他 Android 版本设备或模拟器上验证 UI、权限、解码和生命周期；未实际运行过的版本在交付说明中列为待验。
